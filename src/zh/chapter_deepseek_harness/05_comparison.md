# 15.5 横向对比：DeepSeek Harness vs Claude Code / OpenClaw / Hermes

横向比较先明确要替换哪一层，再判断候选是否满足同一个任务。聊天入口、编程产品、跨会话记忆和组件扩展回答不同的问题，不能凭一个功能列表把它们排成优劣顺序。

本节比较的是本书四个案例的观察重点。具体产品能力需要在明确版本和配置中验证；没有运行的部分保留为未知，不据案例概览作功能背书。

## 先分清层次与实验对象

| 案例 | 本书的观察层次 | 固定任务中要检查什么 | 可以跳过的情况 |
|---|---|---|---|
| [第12章 OpenClaw](../chapter_openclaw/README.md) | 个人助理产品的聊天入口与会话边界 | 选择一个渠道，核对消息身份、会话范围、允许工具及失败提示 | 不需要聊天入口，或接入条件不满足 |
| [第13章 Hermes](../chapter_hermes/README.md) | 跨会话记忆、技能候选与调度的产品／架构案例 | 在未用于编写技能的固定任务上比较启用前后，并验证删除、停用和回退 | 没有长期积累需求，或不能独立判断改进 |
| [第14章 Claude Code](../chapter_claude_code/README.md) | 编程产品的代码操作、上下文与授权 | 用固定缺陷核对补丁、真实测试、修改范围和失败记录 | 任务不涉及编程，或运行条件无法复现 |
| [第15章 DeepSeek Harness](./README.md) | 可替换组件与插件生命周期的架构案例 | 明确一个替换目标，检查输入输出、状态、权限和失败清理 | 没有组件替换需求，或维护成本超过收益 |

“产品”是实验中的使用对象，“架构案例”是阅读与借鉴方式。同一个对象可以承担两种用途，但读懂一张架构图并不证明产品已经在自己的任务中通过验收。

如果问题只是模型、工具的适配重复，先考虑[第10章 LangChain](../chapter_langchain/README.md)；如果问题是显式状态、分支和恢复，再考虑[第11章 LangGraph](../chapter_langgraph/README.md)。开发库可以与自己的宿主结合，不必为了选择案例而安装四个产品。

## 用同一任务保持比较条件

对已有资料计算任务，先保留[贯穿项目](../learning_project.md)的输入、预期、来源、权限、预算和独立验收结果。候选实验只改变当前要研究的层次。例如，比较聊天入口时保留后端计算契约；比较组件替换时保留输入输出与失败判据。

| 条件 | 比较前固定 | 实验后保存 |
|---|---|---|
| 任务 | 一份输入与明确预期；包括缺证据、冲突和非法动作 | 实际产物、执行状态与独立验收结论 |
| 权限 | 相同用户、可访问数据、允许工具和确认规则 | 获准与拒绝动作、检查发生的位置 |
| 模型模式 | 固定输出或真实模型；真实模式记录模型及参数 | 模型调用与工具调用分别计数，记录耗时与错误 |
| 生命周期 | 同样的预算、停止条件和待测试故障点 | 重试、取消、恢复或清理记录；未覆盖项另记 |
| 版本 | 产品或源码的确切版本、配置和接入环境 | 复现步骤、依赖差异与不可比较之处 |

对于编程任务，应固定缺陷仓库和未改写的验收测试；对于记忆或技能实验，应固定生成候选之外的测试集。不能把各产品各自擅长的不同演示，拼成一张同题性能表。

本书没有四产品的统一离线适配器。仓库的资料计算 fixture 验证自身的契约与编排，不调用这四个产品；已有两个开发库示例也使用不同任务。读者移植同一契约后，需要实际执行对应实验。无法运行时写“未运行”，无法保持相同条件时写“不可直接比较”。

## 扩展格式相似不等于可以互换

同名的 `SKILL.md` 文件不能单独证明兼容性。迁移一种技能至少需要核对：

- 文件内容与元数据怎样解析，哪些字段被忽略或拒绝。
- 依赖的工具名称、参数、返回值和错误是否一致。
- 运行环境、凭据范围与文件路径是否相同。
- 授权、确认、超时和失败处理由哪一层执行。
- 原来的独立验收用例在目标环境中是否仍然成立。

同样，能够配置一个模型不代表已覆盖其工具协议、流式错误和恢复行为；能够加载插件也不代表任意内核都能替换。应把每次兼容结论限定到实际验证的版本、接口和用例。

在一台机器上分别使用几个产品，只说明它们分别被使用。若希望共享记忆、工具或技能，仍需明确定义数据所有者、同步接口、冲突处理和权限，不把并存当作已经集成。

## 保留采用或跳过的记录

| 决策项 | 填写方式 |
|---|---|
| 当前问题 | 现有实现在哪个可复现的场景失效或难以维护？ |
| 候选与替换范围 | 替换入口、状态机制、组件，还是使用一个产品完成独立任务？ |
| 证据 | 相同任务的成功与失败结果，以及版本、配置、调用和权限记录 |
| 结论 | 采用一个已验证的改变、保留原实现，或继续验证一个明确未知项 |
| 停止与回退 | 未满足正确性、权限、数据或维护要求时，停止迁移并保留原有产物 |

没有新增维护问题时可以跳过产品迁移；候选实验没有通过时也可以保留最小实现。一次成功演示不保证其他任务或未来版本仍适用，新的版本和配置需要重新经过相关验收。

把这份记录带到[第15.7节](./07_summary_and_decision_matrix.md)，与[第三部分选择指南](../part3.md)使用相同的判断顺序：问题、层次、候选、固定任务和停止条件。
