# 第18章 Agent 的评估与优化

**阅读层次**：核心必读；从第一个实战开始回查。

## 本章迭代

- **上一版的不足**：每章的几个用例能说明局部行为，却不能回答改动是否退化、真实任务是否更好，或成本是否可接受。
- **本章增加**：把早期任务卡、反例和轨迹整理为版本化回归集，固定独立判据，分开报告质量、拒绝、失败、耗时和调用成本。
- **怎样验证**：先运行 `reference_code/evidence_assistant/tests/test_project_contracts.py` 与 `reference-agent/tests/test_evaluation.py` 的固定预期和错误产物反例，再为自己的真实任务保留独立测试集。比较同输入、同配置的改前/改后结果；候选自身评分不能决定发布。现有离线测试不测真实模型收益。
- **下一步**：带着失败分类和发布门禁进入[第19章](../chapter_21_security/README.md)。本章不要求采用某个框架，也应从第3章起回查。

> 如何知道你的 Agent 是"好"还是"不好"？评估和优化是从"能用"到"好用"的关键。

---

## 从第一个实战开始建立评估基线

第一次读第3章实战时，先完成三件事：保存固定输入与预期结果，记录工具轨迹，加入至少一个失败用例。以后增加记忆、检索或规划时，重跑相同问题，再追加能暴露新能力缺陷的用例。不要把模型给自己的分数直接当作验收结论。

仓库已有一个可离线复现的起点：在 `reference-agent/` 中安装 `pip install -e ".[dev]"`，然后运行 `python -m pytest tests/test_evaluation.py -q`。它只对随附固定样本做简单匹配，用于理解回归门禁；真实任务还应分别检查正确性、证据、工具行为、成本和失败状态。每条记录至少保留输入、期望、实际结果、判定理由与配置版本。

## 🎓 学习目标

完成本章学习后，你将能够：

- ✅ 掌握评估 Agent 表现的系统方法（规则评估、LLM 评估、人类评估）和核心指标
- ✅ 了解 SWE-bench、GAIA、WebArena 等主流基准测试
- ✅ 实施系统化的 Prompt 调优迭代流程
- ✅ 掌握成本控制与性能优化的实践技巧（模型路由、缓存、压缩）
- ✅ 构建可观测的 Agent 系统（日志、追踪、监控）
