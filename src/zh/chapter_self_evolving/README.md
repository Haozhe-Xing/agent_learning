# 第25章 自我进化与持续学习

**阅读层次**：研究选读；先完成应用与评估基线，不要求先做模型训练。

## 本章迭代

- **上一版的不足**：应用有固定验收，但每次改 Prompt 或技能仍靠人工试错；一个候选在看过的样例上分数更高，可能只是过拟合，也可能削弱权限约束。
- **本章增加**：把失败轨迹转为候选修改，分别管理候选生成、固定评估、版本晋升和回滚；限定可修改对象，保留独立测试集与不可改写的执行边界。
- **怎样验证**：已有 `examples/auto_research_demo/main.py` 用标准库实现合成分类任务的候选搜索，可观察配置、分数和保留/拒绝记录；它不是 Agent 提示或技能的自动改写器，评估隔离也仅是代码组织。读者扩展：接入自己的项目与独立测试，验证退化候选被拒绝、失败可回滚且测试/权限不能被候选修改，再报告收益。
- **下一步**：将通过独立测试的候选送回[第18章回归门禁](../chapter_20_evaluation/README.md)，通过[第19章边界检查](../chapter_21_security/README.md)后按[第20章](../chapter_22_deployment/README.md)发布。若瓶颈在模型参数，可选择[第24章](../chapter_agentic_rl/README.md)，不必把权重训练作为 Prompt 或技能改进的起点。

> 🧬 *"普通 Agent 解决任务；自我进化 Agent 解决任务，并学习如何更好地解决下一类任务。"*

前面的章节已经建立了能执行任务、能验收和能部署的应用。接下来的问题是：如何利用反复出现的失败改进下一版本，而不让系统改坏自己的测试和执行边界？本章可直接承接综合项目，不要求先完成第24章的权重训练。

本章聚焦一个贯穿全书的主题——**自我进化（Self-Evolution）**：让 Agent 把每一次交互的副产物（成功模式、失败教训、可迁移技能）沉淀下来，并在后续任务中自动复用与提升。

本章把“自我进化”拆成三个层次：

| 节 | 内容 | 核心收获 |
|----|------|---------|
| 25.1 | Prompt 自动调优 | 从手工提示词到自动搜索/反思进化：APE、OPRO、DSPy、TextGrad、GEPA |
| 25.2 | Self-Evolution Agent | 自我改进闭环架构、工程落地路径、前沿研究全景、三角色视角与被低估的“总结者” |
| 25.3 | Agentic 数据飞轮 | 轨迹收集→质量过滤→奖励标注→训练迭代的持续自我强化闭环 |

**进阶脉络**：进化“提示词” → 进化“整个系统行为与前沿能力” → 建立“持续数据飞轮”。从 25.1 的 Prompt 级进化，到 25.2 的系统级闭环与研究前沿，再到 25.3 的工程化持续迭代系统，逐层加深。
