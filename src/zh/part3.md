# 第三部分：框架与实现选择篇

前两部分已经建立最小 Agent 的工具、记忆、规划、证据、上下文和执行约束。本部分解决实现方式的选择：先指出现有流程的具体维护成本，再判断是否引入开发库、使用现成产品，或只借鉴一个架构设计。

第10–11章是按需求采用的开发库；第12–15章是产品与架构案例选读。LangChain 与 LangGraph 可以组合，也可以分别学习，不构成每个项目都要安装的连续技术栈。应用开发无需先学第24–25章的研究进阶内容。

## 带着已有产物进入本部分

保留[贯穿项目](./learning_project.md)的任务输入、来源、工具权限、调用预算、执行记录与独立验收结果。引入新实现时，只替换承担当前问题的部分，检查原来的成功和失败用例是否仍成立。

例如，适配代码重复时先研究接口复用；中断后无法安全继续时再研究状态与恢复。能够继续工作的最小实现也可以是最终选择。

## 先分清比较的层次

| 层次 | 本部分的学习对象 | 选择时要回答的问题 |
|---|---|---|
| 开发库 | LangChain、LangGraph | 哪部分代码和运行状态由库承担，哪些业务约束仍由应用负责？ |
| 现成产品 | OpenClaw、Hermes、Claude Code | 是否适合目标入口和任务？权限、配置、数据与失败记录是否满足要求？ |
| 架构案例 | DeepSeek Harness，以及前述产品中的设计 | 哪个接口或控制机制值得借鉴？是否需要移植该机制，还是只需理解它？ |

“架构案例”是本书的教学用途。一款产品也可以作为架构案例阅读；这种阅读不能代替运行验证，更不能证明不同产品可以直接拼接成一个系统。

## 从问题选择章节

| 眼前的问题 | 实现层次与候选章节 | 固定任务怎样验证 | 不选或停止条件 |
|---|---|---|---|
| 模型、工具、消息适配代码反复出现 | 开发库：[第10章 LangChain](./chapter_langchain/README.md) | 保留输入、权限与验收集，对照适配前后的调用记录、错误返回和维护代码 | 现有接口已足够清楚，迁移只增加依赖 |
| 分支、暂停、恢复或人工确认难以追踪 | 开发库：[第11章 LangGraph](./chapter_langgraph/README.md) | 固定同一中断点与失败输入，核对恢复位置、重复副作用、预算和结束状态 | 短流程无需恢复，显式循环已足够表达 |
| 想从聊天入口使用个人助理 | 产品案例：[第12章 OpenClaw](./chapter_openclaw/README.md) | 只选择一个目标渠道，验证身份、会话、工具权限、错误提示与任务结果 | 只需要后端服务，或渠道访问与权限条件不满足 |
| 想研究跨会话记忆和技能积累 | 产品／架构案例：[第13章 Hermes](./chapter_hermes/README.md) | 固定未用于编写技能的任务，对照记忆或技能启用前后；记录审查、停用和回退结果 | 无长期使用需求，或不能独立判断改动是否有效 |
| 想使用编程助理或研究代码操作边界 | 产品／架构案例：[第14章 Claude Code](./chapter_claude_code/README.md) | 固定代码任务，检查补丁、真实测试、授权动作和失败记录 | 任务与编程无关，或运行条件无法复现 |
| 想研究组件替换与插件生命周期 | 架构案例：[第15章 DeepSeek Harness](./chapter_deepseek_harness/README.md) | 在明确版本与配置下替换一个组件，核对接口、状态兼容和失败清理 | 只需使用助理，或没有证据证明替换收益大于维护成本 |

这张表给出本书的阅读与实验入口。一次候选实验未通过权限、数据或正确性要求，就应停止迁移、保留原实现并记录原因。不要为了完成表格而启用所有工具或接入个人数据。

## 固定任务与配套示例的边界

仓库提供三类材料，验证范围不同：

| 材料 | 已提供的入口 | 能观察什么 | 尚不能据此推出什么 |
|---|---|---|---|
| 本地资料调研参考应用 | `python -m reference_code.evidence_assistant` | 多资料、多问题的检索、计划、上下文计量、引用报告和失败状态 | 开放网络研究、完整语义验收或产品优劣 |
| 基础计算练习 | `python -m reference_code.evidence_assistant.demo --all` | 六阶段的数据流、单位处理、权限、预算和独立数值验收；标记 `offline-fixture` | 真实模型理解能力或网络搜索质量 |
| 开发库配套示例 | `examples/chapter12/customer_service.py`、`examples/chapter13/content_workflow.py` | 固定模型输出下的工具编排与状态图行为；目录名保留历史编号 | 两个不同任务的结果可以直接比较，或已经代表真实模型质量 |
| 产品与架构章节 | 第12–15章的案例说明 | 分析入口、状态、权限、扩展等设计，并制定复现计划 | 已有四款产品的统一离线适配器，或案例都已在相同环境运行 |

已有框架示例使用不同任务。真正比较两种实现时，需要把**同一份任务输入、预期结果和失败用例**迁移到候选实现，再分别运行；不能把各自演示成功当成公平对照。真实模型模式应单独记录模型与配置、调用量、耗时和失败原因。

## 章节怎样接起来

第10章关注接口与工具编排。完成后，如果新增问题是“中断后从哪里继续”“哪些动作不能重复”“什么时候等待确认”，再进入第11章；只需要接口集成的读者可以在此停止。

第11章把执行过程变成可检查的状态变化。第12–15章不继续增加必装组件，而是提供不同场景的设计样本：聊天入口、跨会话积累、代码操作、组件扩展。任选与任务相关的一章，把观察到的机制映射到已有助手，并保留能证明作用的记录。

完成一次候选对照后，用[第15.7节](./chapter_deepseek_harness/07_summary_and_decision_matrix.md)整理选择理由。读完的产品数量不作为完成标准；能解释当前选择、展示验证证据并指出适用边界，才完成本部分。

## 下一步按新问题分流

- 有可独立分工的任务，且希望验证协作是否改善结果：进入[第16章 多 Agent 协作](./chapter_18_multi_agent/README.md)。先与单 Agent 对照，角色增加本身不算收益。
- 工具或 Agent 需要跨进程、服务边界互通：进入[第17章 Agent 通信协议](./chapter_19_protocol/README.md)。协议需求与角色数量分别判断。
- 需要把已有记录变成回归门禁：进入[第18章 评估与优化](./chapter_20_evaluation/README.md)，继续[第19章 安全与可靠性](./chapter_21_security/README.md)、[第20章 部署与生产化](./chapter_22_deployment/README.md)。
- 已明确任务与验收目标：按需选择第21–23章的[编程助手](./chapter_23_coding_agent/README.md)、[数据分析](./chapter_24_data_agent/README.md)或[多模态](./chapter_25_multimodal/README.md)项目。
