# 3.1 为什么 Agent 需要工具？

模型能写出“已查询”或“已计算”，不代表系统真的做过。工具的第一项价值是提供可核对的动作与观察：哪份资料被查到、传了哪些参数、函数返回什么、失败在哪里。是否需要工具由任务决定，不能因为工具可用就每次都调用。

## 从任务缺口选择能力

| 缺口 | 可考虑的工具 | 仍需检查 |
|---|---|---|
| 指定资料不在当前输入里 | 本地检索或获准的数据接口 | 来源、版本、可见范围、空结果 |
| 数值需要确定的运算规则 | 受限算术或领域计算器 | 单位、精度、输入范围、独立预期 |
| 需要外部动作 | 受授权的写入接口 | 对象范围、确认策略、幂等、实际回执 |
| 只是改写已给文字 | 可能无需工具 | 输出是否满足要求 |

模型参数中的知识可能过时或缺少任务所需的私有资料；工具能引入新观察，但搜索结果也可能错误。模型输出调用意图不会自动拥有网络连接、凭据或数据库权限，真正访问资源的是宿主执行器。

## 一个实际函数观察

```python
import json
from reference_code.tool_calling import ToolHost

host = ToolHost(allowed_tools=("calculate",))
observation = host.execute("calculate", json.dumps({"expression": "12345 * 67890"}))
assert observation == {"ok": True, "value": {"value": 838102050}}
print(observation)
```

这里执行了共享的受限算术解释器，结果为838102050。它证明这个表达式在本实现下的运算结果，不证明表达式来自正确的业务数据，也不证明金额单位正确。模型选择、参数来源、函数执行和任务验收要分别看。

## 提议、执行、验收三份记录

1. **提议**：模型请求 `calculate`，参数是JSON文本；名字和参数都尚未获得信任。
2. **执行**：宿主核对注册工具、当前许可、参数类型和值、剩余预算，才调用函数。
3. **验收**：独立要求核对最终值、单位、来源和缺失信息；工具正常返回不等于整个任务完成。

不能把工具描述写成“只读”就认为资源不可写，也不能用通用解释器代替明确合同。文件、SQL、邮件等动作需要资源级授权及自己的执行约束；本章不提供任意路径、Shell或发送工具。

## 失败也属于工具结果

参数错误、权限拒绝、没有候选、网络超时和独立验收失败含义不同。返回空文本或一条貌似答案的报错字符串，会让后续流程混淆成功与失败。配套使用 `ok/code/value` 结构，并保留任务未完成状态。

日志也应按用途记录：调用ID、工具名、状态和必要的来源可用于核对；完整参数、网页、客户记录或异常正文可能敏感，不应无差别永久保存。固定夹具中的可见轨迹不是生产日志策略。

练习为“继续昨天的发布检查”写边界表：需要哪些资料读取、哪些计算、是否有写入；分别列出授权主体、最大输入、失败状态和完成证据。先保留只读最小路径，再阅读下一节的协议。
