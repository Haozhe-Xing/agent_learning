# 第11章 LangGraph：构建有状态的 Agent

**阅读层次**：工程进阶；需要显式状态、路由或恢复时选用。

工具能被调用之后，下一类问题是执行到哪一步、为什么重试、何时等待确认以及如何停止。本章用节点、边和共享状态表达这些变化，并保留任务原有的输入、工具结果与验收要求。

## 本章迭代

- **上一版的不足**：业务流程依赖隐含控制流，分支、修改次数和停止原因难以检查。
- **本章增加**：显式状态、条件边与有上限的循环，并讨论人工确认与恢复所需的状态记录。
- **怎样验证**：用固定评分的修改审查示例检查状态和次数；若要比较原任务，则迁移同一契约与反例。持久恢复、人工确认和副作用去重还须分别补实验，不能由图能跑通直接推出。
- **下一步**：有可独立分工的任务时读[第16章 多 Agent 协作](../chapter_18_multi_agent/README.md)；否则先把状态记录整理为[第18章 评估](../chapter_20_evaluation/README.md)的回归用例。

## 验证与材料边界

配套入口是 `examples/chapter13/content_workflow.py`，目录保留历史编号。固定输出控制审查分数，实际执行状态图；它验证路由与修改次数，不能评估模型的审查质量，也没有替所有恢复机制提供统一验收。

学习本章不要求引入多个 Agent。是否分角色、是否跨服务通信、是否使用状态图，应分别由任务问题决定。
