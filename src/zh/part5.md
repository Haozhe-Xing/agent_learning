# 第五部分：验证与部署篇

前面的每一次迭代都应留下输入、预期、实际结果和失败记录。本部分把这些分散证据整理为可重复的门禁，再确定运行边界和服务交付方式。评估与安全检查从第3章开始使用，在这里集中学习；无需等到读完框架章节才开始。

| 章节 | 上一版的不足 | 本章交接产物 | 继续条件 |
|---|---|---|---|
| [18 评估与优化](./chapter_20_evaluation/README.md) | 一次演示成功，不能证明改动有效 | 固定回归集、逐例判定、配置和成本记录 | 同输入对照基线；未通过门禁不发布 |
| [19 安全与可靠性](./chapter_21_security/README.md) | 正常用例通过，仍可能越权或受资料指令影响 | 信任边界、权限矩阵与攻击/拒绝记录 | 文档不能变成授权；危险动作在宿主执行前被拒绝 |
| [20 部署与生产化](./chapter_22_deployment/README.md) | 本地函数可用，不等于服务可维护 | API 契约、运行配置、失败响应与恢复检查表 | 接口结果与本地判定一致，超时和故障有明确结果 |

仓库 `reference-agent/` 是可运行的接口、评估和基础防护教学底座。真实模型质量、生产鉴权、持久任务恢复、容器和负载验证须按部署目标补充；“服务启动”不能代替“业务验收通过”。

完成后选择[第六部分](./part6.md)的一个领域项目；若只需交付当前任务，也可在这一阶段停止。只有固定评估表明存在模型行为瓶颈时，才进入[研究进阶](./part7.md)。
