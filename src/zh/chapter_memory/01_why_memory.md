# 4.1 为什么 Agent 需要记忆？

“继续上次的方案”包含一个隐含要求：应用要找到正确用户、正确项目的那份方案，并判断它是否仍然有效。把更多聊天文字塞进模型并不能自动满足这个要求。记忆系统解决的是**选择、保存和召回哪些状态**，不是让模型参数在每次对话后自行更新。

## 三种责任，不是三种固定数据库

![记忆的三种责任与保留边界](../svg/chapter_memory_01_memory_types.svg)

| 责任 | 保存什么 | 生命周期与边界 |
|------|----------|----------------|
| 短期记忆 | 当前会话的消息、必要摘要 | 送入模型的视图受预算限制；服务端是否保留日志另作规定 |
| 工作记忆 | 当前任务的输入引用、中间结果、待办和失败状态 | 按用户与任务隔离；完成、取消或过期时按策略清理 |
| 长期记忆 | 经同意保留的偏好、事实或项目记录 | 跨会话使用；需要来源、更新、撤回和删除机制 |

这是应用设计上的分工，可以共用存储，也可以分开实现。短期历史不会因为会话结束就必然从磁盘消失；长期记忆也不等于永久保存或必须使用向量数据库。关系数据库、键值查询、关键词和向量检索各有适用范围。

例如，“请用简短答案”可能是当前轮的要求，也可能是用户希望跨会话保存的偏好。先确认适用范围，再决定是否持久化。“不要再记住我的职业”则需要删除可检索记录，并使依赖它的缓存、摘要或索引不再继续提供该信息；仅修改当前提示词不够。

## 没有记忆与错误记忆都会出问题

| 场景 | 需要核对的证据 | 不应采取的捷径 |
|------|----------------|----------------|
| 继续上次任务 | 用户/项目/任务标识与最后状态 | 只凭相似标题选历史 |
| 偏好改变 | 用户明确更正及适用时间 | 一直把旧偏好当事实 |
| 对话超出预算 | 被保留的完整消息与删减报告 | 静默裁掉当前问题 |
| 多用户共用助手 | 每次读写的授权主体与过滤条件 | 把客户端传来的用户名当身份认证 |
| 忘记请求 | 活动存储、派生索引和缓存的清理结果 | 写一个 `deleted` 标签却照常召回 |

有时最合适的方案是不增加长期记忆：一次性公开问答可以无持久化，当前任务的临时结果可在任务状态中保留。不能因为存储便宜，就默认保存姓名、职业、全部对话或模型推测的用户画像。

## 先跑最小的同意、隔离和删除练习

仓库的 `reference_code/evidence_assistant/memory.py` 提供一个 SQLite 基线。以下代码可从仓库根目录运行，使用临时文件，不调用模型：

```python
from pathlib import Path
from tempfile import TemporaryDirectory
from reference_code.evidence_assistant.memory import MemoryStore

with TemporaryDirectory() as folder:
    path = Path(folder) / "memory.sqlite"
    store = MemoryStore(path)
    try:
        store.put("alice", "style", "concise")
    except PermissionError:
        print("write denied without consent")
    store.put("alice", "style", "concise", consent=True)
    store.put("bob", "style", "detailed", consent=True)
    store.close()

    store = MemoryStore(path)
    assert store.records("alice") == {"style": "concise"}
    store.delete("alice")
    assert store.records("alice") == {}
    assert store.records("bob") == {"style": "detailed"}
    store.close()
```

这里 `consent=True` 是宿主已获得同意后的显式输入；字符串 `"yes"` 或数字 `1` 不能代替布尔同意。示例的主体标识由测试直接给出，真实服务必须先认证并授权，不能让模型任选 `alice` 或 `bob`。SQLite 的删除证明当前记录不再可查询，不证明独立备份或磁盘残留已被安全擦除。

这个基线没有自动记忆提取、有效期、逐条来源审计或语义检索。它的意义是先验证最基本的合同，再按任务需要增加能力；不能把这些未实现能力都算作“已有记忆系统”。

## 每条记忆都要回答四个问题

1. **谁可以使用？** 用户、项目和可见范围由宿主确定，检索先过滤权限，再按相关性排序。
2. **为什么可以保存？** 记录明确的用途与同意；自动提取只能产生候选，不能替用户批准持久化。
3. **依据是什么？** 区分用户原话、外部资料、工具结果与模型推测，保留来源和版本。
4. **何时失效？** 更正、撤回、到期和任务结束都可能触发更新；删除还需检查派生材料。

召回的记忆仍是带来源的数据。记录中出现“忽略系统规则”不会变成新的系统授权；偏好“省略解释”也不能取消任务要求的证据或权限检查。内容被保存，只说明它进入了存储，不能证明内容正确或当前仍适用。
