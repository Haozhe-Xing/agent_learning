# 第4章 记忆系统（Memory）

**阅读层次**：核心必读；论文与分层记忆实践可二刷。

## 本章迭代

- **上一版的不足**：光行时间已经能算对，但用户说过“以后用毫秒”后，新会话仍可能输出秒；把整段历史永久保存又会造成越权写入和用户串扰。
- **本章增加**：把经同意的 `output_unit` 偏好保存为用户范围内的记忆，并让读回值实际参与换算；将长期偏好与当前任务的工作状态分开。
- **怎样验证**：已有入口 `python -m reference_code.evidence_assistant.demo --stage memory --output-unit milliseconds` 展示记忆参与换算；`python -m unittest reference_code.evidence_assistant.tests.test_learning_path.MemoryTests` 检查持久化重开、隔离、删除与同意边界。交付存取记录和带单位结果。共享阶段本身使用临时 SQLite 文件（阶段结束时清理），跨会话持久化由独立测试验证；向量召回质量仍需真实任务集。
- **下一步**：即使记住“用毫秒”，Agent 仍可能漏掉提取步骤或重复计算。在[第5章](../chapter_planning/README.md)为同一任务记录步骤、依赖和完成条件；记忆解决保留什么，规划解决接下来做什么、何时结束。

记忆是一组可检查的存取与生命周期机制。对话历史、当前任务状态和获准跨会话保存的资料有不同用途；长期记忆也可以是结构化数据库，不等同于向量库。

## 学习目标

完成核心练习后，应能：

- 区分消息历史、任务工作状态与持久记忆的用途和生命周期。
- 在字节预算内保留固定规则、当前提问与完整轮次，并说明它与模型token预算的区别。
- 用SQLite或显式向量的Chroma练习同意、主体隔离、重开和删除。
- 为中间产物保存来源与独立验证状态，不把模型提议当作事实。
- 运行个人助手配套的已声明路径，识别真实模型、存储与宿主认证分别需要什么。

## 参考代码与阅读范围

`reference_code/evidence_assistant/`保留贯穿项目及SQLite记忆；`reference_code/memory_rag/`提供4.1–4.4的历史、状态与向量机制练习。先用`python -m reference_code.memory_rag history`观察裁剪，再按需要选择`working`、`chunks`或`vectors`。向量模式需要锁定Chroma依赖，固定向量只验证数据库机制。

运行结果需要同时说明来源、权限、预算和失败；保存成功不证明召回正确，逻辑删除也不证明全部备份已擦除。自动摘要/偏好提取、真实嵌入质量、远程存储及产品SDK须另行验证。外部记忆产品不作为本章必装依赖，也不引用未复现的当前榜单作选型依据。
