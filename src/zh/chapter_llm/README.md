# 第2章 大语言模型基础

**阅读层次**：核心必读；2.6–2.8 按需选读。

## 本章迭代

- **上一版的不足**：第1章有了任务卡，但模型怎样接收材料、返回什么、在哪些情况下不能使用结果，还没有可复现的记录；流畅的数字回答也可能算错。
- **本章增加**：把任务卡变成包含资料、目标单位和输出要求的消息，保存模型名称、调用参数、原始响应与错误状态，建立后续工具版本的对照基线。
- **怎样验证**：读者练习：保存同一任务的两次调用，分别检查非空输出、格式和数值；再记录一次缺少资料的回答。交付调用记录与人工判定，不以两次输出评价模型总体质量。实际模型调用需要凭证；本章没有用离线固定结果代替这项实验。
- **下一步**：在[第3章](../chapter_tools/README.md)把数值工作交给工具。2.7 的模型架构与 2.8 的训练数据准备可在应用跑通后，结合[第24章](../chapter_agentic_rl/README.md)回读；它们不是第一次工具实战的前置条件。

> 工欲善其事，必先利其器。在开始构建 Agent 之前，我们需要深入理解它的"大脑"——大语言模型（LLM）。

## 为什么 Agent 开发者需要理解 LLM？

很多 Agent 框架（LangChain、LangGraph 等）将模型调用封装得很好，初学者可以快速上手。但当你的 Agent 出现以下问题时，理解 LLM 底层机制就至关重要：

- 输出不稳定，同样的问题得到不同答案
- 模型"幻觉"——信心十足地给出错误答案
- Token 超限，长对话被截断
- 成本过高，需要优化 Prompt 减少消耗

理解 LLM 就像理解发动机原理——即使你不造发动机，懂原理也能让你成为更好的驾驶员。
