# 第19章 安全与可靠性

**阅读层次**：核心必读；从第一次工具调用开始回查。

## 本章迭代

- **上一版的不足**：正常任务通过仍不能证明恶意资料不会改变指令、其他用户无法读取记忆，或危险工具会在执行前被拦截。
- **本章增加**：按模型、资料、用户身份和工具服务划分信任边界，把权限、敏感数据处理和拒绝路径落实到宿主检查。
- **怎样验证**：已有 `reference-agent/tests/test_security.py` 和 `reference_code/evidence_assistant/tests/test_learning_path.py` 验证基础输入规则、记忆隔离及未授权调用不进入执行器。读者还须对自己的后端验证注入、跨用户、越权与日志泄露；规则过滤和进程组管理均不能替代隔离执行环境。
- **下一步**：权限矩阵、攻击记录与仍未覆盖的风险是[第20章部署](../chapter_22_deployment/README.md)的输入。从第一次工具调用起就使用本章的基本检查。

> Agent 拥有了工具和自主性，安全问题就变得尤为重要。这一章是从"能用"到"敢用"的关键。

---

## 从工具调用开始检查执行边界

安全检查应贯穿前面的实战。第3章限制可调用工具和计算资源，第4章检查记忆写入同意、删除和用户隔离，第6章区分文档资料与执行指令，第10–11章验证业务鉴权和停止条件。这些检查不需要等到部署时才做。

每个实战至少记录：数据从哪里来、允许执行什么动作、由哪段代码强制检查权限、拒绝或超限时如何返回。用一条正常输入和一条越权输入验证执行路径；提示词中写了“禁止”不等于工具后端已经拒绝。基础防护测试可在安装 `reference-agent/` 的开发依赖后运行 `python -m pytest tests/test_security.py -q`，它只覆盖随附规则，不代表已完成生产安全验证。

- ✅ 实现权限控制和沙箱隔离机制
- ✅ 了解敏感数据保护的工程实践（PII 检测、脱敏）
- ✅ 理解 Agent 对齐与行为可控性的核心挑战
- ✅ 掌握 Guardrails 运行时防护与红队测试方法论
